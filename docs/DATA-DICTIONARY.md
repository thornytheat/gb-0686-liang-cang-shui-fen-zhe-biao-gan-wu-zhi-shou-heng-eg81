# 字段与计算定义

id、bin为字符串，保留前导零；version为正整数。gross、tare为毛重与皮重，unit仅kg或t。净重先换算kg，且毛重不小于皮重。
moisture、impurity为百分数，取值[0,100)，水分超过max_moisture拒收。标准水分必须小于收购上限且低于100。
净粮=净重×(1-杂质/100)，干物质=净粮×(1-水分/100)，折标重=干物质/(1-标准水分/100)。
单价CNY/kg，按未舍入折标重计算总额，再以最大余额法分配分币，余数相同按id升序。全部金额和重量为Decimal，JSON以字符串输出。
同键最高版本采信；同版数值不一致时该键所有行隔离，完全相同则保留最早行。旧版与重复行计入隔离，保证输入行数平衡。
时间仅用于运行清单，保存UTC偏移。空值、哨兵、零分别处理，空文件/仅表头/全空行返回不同原因码。规则参数纳入批次哈希。

## 仓容分配（M8）

`bin_capacity` 为仓号到干物质容量 kg 的映射，可用 JSON 对象或 `仓1=12000,仓2=11000` 文本；单位是干物质 kg，与 `dry_kg` 同尺度。
分配口径：按原始行号（到车顺序）逐车处理，本仓优先。
- 本仓余量足够：整车入本仓，`part_count=1`。
- 本仓不足：先占满本仓余量，剩余部分整段落进另一个仓，且选余量最小又能放下的仓（best-fit）。一车最多两段，`part_no` 为段号，`split=true`。
- 本仓余量为 0 而另一仓能整车放下：整车换仓，`relocated=true`，段数仍为 1，车次保持完整。
- 除本仓外没有单仓能整段容纳剩余部分：整车暂缓（`deferred`），不占任何仓容，不写 `bin_entries`，也不进入隔离清单；证据 CSV 标记为 `CAPACITY` 供复核。
每段净重、折标重、金额按干物质占比拆分，第二段用整车减第一段；逐车校验各段 `dry_kg` 之和等于整车，第二段金额按分舍入后同样与整车相减。任何仓 `occupied ≤ capacity`。
批次幂等键是输入内容 SHA256（`batch`），不是 `run_id`：同一批磅单改参数重跑时以差额替换本批旧占用，不会二次占容；同一 `run_id` 重复执行直接复用旧结果。
仓账提交为单事务：先校验每仓 `opening_kg` 与当前账面一致，再累加。任一仓超容或账面已变化则整批回滚，保留入账前旧版库容，不留下半条记录。
